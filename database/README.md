# CampusPlan Database

CampusPlan의 MySQL 데이터베이스 설계와 SQL 스크립트를 관리하는 디렉터리입니다. 학점 집계, 봉사활동 승인 및 누적 시간 반영, 졸업요건 진단의 기준과 처리는 데이터베이스 구조 및 객체와 일관되게 관리합니다.

> 현재 `schema/`, `routines/`, `seeds/` 폴더는 있으며, 각 폴더에는 안내용 README만 있습니다. 아래 SQL 파일은 향후 추가할 때 사용할 권장 이름입니다.

## 1. 기술 환경

- **DBMS**: MySQL
- **문자셋 권장값**: `utf8mb4`
- **관리 도구**: MySQL Workbench, DBeaver 등
- MySQL 버전과 콜레이션은 팀 개발 환경을 확정한 뒤 동일하게 적용하고 문서화합니다.

## 2. 디렉터리 구조

```text
database/
├── README.md
├── schema/
│   ├── README.md
│   └── 01_schema.sql                 # 추가 예정: 데이터베이스·테이블·제약 조건
├── routines/
│   ├── README.md
│   ├── 02_triggers.sql               # 추가 예정: 이수 여부·학점 집계 트리거
│   ├── 03_procedures.sql             # 추가 예정: 봉사활동 일괄 승인 프로시저
│   └── 04_views.sql                  # 추가 예정: 졸업요건 진단 뷰
└── seeds/
    ├── README.md
    ├── 05_seed_master.sql            # 추가 예정: 확인된 기준 데이터
    └── 06_seed_test.sql              # 추가 예정: 개발·시연용 테스트 데이터
```

### 폴더별 관리 대상

- `schema/`: 테이블, 기본 키·외래 키, 제약 조건, 인덱스 등 데이터 구조
- `routines/`: Trigger, Stored Procedure, View
- `seeds/`: 과목·졸업요건 등 기준 데이터와 테스트 데이터

## 3. 주요 데이터베이스 객체

- **Trigger**: 수강 성적 변경에 따른 이수 여부 판별 및 학점 집계를 처리합니다.
- **Stored Procedure**: 학생의 대기 중인 봉사활동을 일괄 승인하고 승인된 봉사시간을 합산합니다.
- **View**: 학생의 학점, 필수과목 이수 및 봉사시간을 졸업요건과 비교해 진단 정보를 제공합니다.

각 객체의 상세 계산 기준은 확정된 스키마와 요구사항에 맞춰 SQL 파일에 기록합니다. 계획서의 SQL 예시는 설계 초안이므로 실제 적용 전에 테이블 구조와 MySQL 동작을 확인합니다.

## 4. 초기 구축 순서

새 로컬 데이터베이스를 구성할 때는 아래 순서를 따릅니다.

1. `schema/01_schema.sql` 실행: 데이터베이스와 테이블 생성
2. `routines/02_triggers.sql` 실행: 트리거 생성
3. `routines/03_procedures.sql` 실행: 프로시저 생성
4. `routines/04_views.sql` 실행: 뷰 생성
5. `seeds/05_seed_master.sql` 실행: 출처를 확인한 기준 데이터 입력
6. `seeds/06_seed_test.sql` 실행: 개발·시연용 테스트 데이터 입력
7. 주요 조회와 데이터베이스 객체 동작 확인

실행 순서가 변경되면 관련 의존성을 확인하고 이 문서도 함께 갱신합니다. 초기화 스크립트를 운영 중인 데이터베이스에 재실행하면 데이터가 중복되거나 변경될 수 있으므로, 각 스크립트가 초기화용인지 반복 적용 가능한지 명시합니다.

## 5. 데이터 관리 원칙

### 기준 데이터와 테스트 데이터 분리

- 공식 자료의 출처와 확인 상태를 기록합니다.
- 공식 자료에서 확인되지 않은 과목이나 졸업 기준은 확정된 기준 데이터로 등록하지 않습니다.
- 임시값과 합성 데이터는 테스트 데이터로 구분하고, SQL 주석에도 테스트용임을 표시합니다.
- 실제 학사 자료와 테스트 데이터는 서로 다른 파일에서 관리합니다.

### 개인정보 및 비밀 정보 보호

- 실제 학생의 학번, 이름, 성적, 계정 정보 등 개인정보를 테스트 데이터나 커밋에 포함하지 않습니다.
- 비밀번호, 토큰, 데이터베이스 접속 정보는 SQL 파일에 넣지 않습니다.

### 스키마와 문서 동기화

- 스키마를 변경하면 ERD, API 명세 및 관련 문서의 테이블명·컬럼명·자료형·상태값도 함께 확인하고 갱신합니다.
- 데이터베이스 변경 사항은 팀원에게 공유하고, 각자 로컬 환경에 반영할 방법을 기록합니다.
