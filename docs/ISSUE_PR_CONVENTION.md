# 이슈 · Pull Request 컨벤션

이 문서는 작업을 이슈로 나누고, 변경 내용을 Pull Request로 검토하는 규칙입니다. 저장소의 `.github/ISSUE_TEMPLATE/` 및 `.github/PULL_REQUEST_TEMPLATE.md` 파일이 GitHub 작성 화면의 양식을 제공합니다.

## 이슈 작성

### 제목 형식

```text
[유형] 작업 내용을 간결하게 작성
```

사용할 유형과 예시:

- `[공통] 인풋 컴포넌트 구현`
- `[페이지] 랜딩 페이지 작업`
- `[API] 랜딩 페이지 API 연동 작업`

### 본문 작성

- **기능 설명**: 구현할 동작과 목적을 설명합니다.
- **Screenshot**: 관련 피그마 시안이나 참고 화면을 첨부합니다. 시안이 없으면 `해당 없음`으로 적습니다.
- **ToDo**: 작업 항목을 완료 가능한 체크박스로 나눕니다.
- **ETC**: 전달할 내용이나 질문이 있을 때 선택해 작성합니다.

작업은 한 이슈에서 추적하기 쉬운 크기로 나눕니다. 새 이슈 생성 화면에서 공통, 페이지, API 템플릿 중 알맞은 항목을 선택합니다.

## Pull Request 작성

PR을 열기 전에 다음 항목을 확인합니다.

- [ ] Reviewer를 지정했습니다.
- [ ] Assignee에 작업자 본인을 지정했습니다.
- [ ] 적절한 Label을 붙였습니다.

### PR 본문

- **주요 사항**: 작업 내용과 주요 변경점을 간략히 씁니다.
- **스크린샷**: 구현 화면을 첨부합니다. 화면 변경이 없으면 `해당 없음`으로 적습니다.
- **리뷰 시 요구사항**: 리뷰어가 확인할 부분이나 질문을 씁니다.
- **연관 이슈 번호**: `Closes #이슈번호` 형식으로 이슈를 연결합니다.

### 대상 브랜치

- 기능 브랜치의 PR은 `develop`을 대상으로 합니다.
- 통합된 변경을 안정 브랜치에 반영하는 PR은 `main`을 대상으로 합니다.
- PR을 열기 전에 원본 브랜치와 대상 브랜치가 의도한 방향인지 확인합니다.
